# Implementation Plan: Core Architecture & UX Improvements

This plan outlines the technical steps required to address the immediate feature improvements we identified in the audit. 

## User Review Required

> [!IMPORTANT]
> **Streaming Responses**: Converting the Cover Letter generator to stream text chunk-by-chunk will require a significant rewrite of both the FastAPI endpoint and the frontend React component fetching it. Please confirm you are okay with changing this UX paradigm.

> [!WARNING]
> **Database Migrations**: The logbook feedback feature requires adding a new column (`feedback_notes`) to your Supabase `logbook_entries` table. You will need to run a small SQL snippet in your Supabase SQL editor to add this column.

## Open Questions
1. **Redis**: The backend codebase already has a `TwoLayerCache` that utilizes Redis if `REDIS_URL` is set in the `.env`. Are you currently running a Redis instance (like Upstash), or should we rely on the memory cache for now until you provision one?
2. **Streaming Provider**: The backend uses Groq/Cohere/Llama for the cover letter generation. Do you want me to implement the streaming logic specifically for the OpenAI-compatible client (which Groq uses)?

## Proposed Changes

---

### 1. AI Matching via BackgroundTasks

Instead of forcing the user to wait while the server loops through every internship to generate an AI score, we will use FastAPI's built-in `BackgroundTasks` to offload the heavy embedding work.

#### [MODIFY] `backend/routers/cv.py`
- Import `BackgroundTasks` from `fastapi`.
- Update the `/upload-and-analyze` endpoint to accept `background_tasks: BackgroundTasks`.
- Extract the CV text, save the URL, and then schedule `background_tasks.add_task(process_matches_in_background, cv_text, internships, user_id)`.
- Immediately return a success JSON response (`"message": "CV uploaded. AI matching is processing in the background."`).

### 2. Email Attachment Overhead

Currently, the backend downloads the user's PDF CV into server memory to attach it to the Resend email. We will change this to include a secure link instead.

#### [MODIFY] `backend/routers/applications.py`
- In `submit_app`, remove the code block that calls `supabase.storage.from_("cvs").download(filename)`.
- Modify the `params["text"]` payload sent to Resend to include: `\n\nView Student CV: {cv_url}`.
- Remove the `attachments` array from the Resend API payload.

### 3. Logbook Feedback Loop

We will allow employers to provide context when they flag a student's daily logbook entry.

#### [NEW DATABASE SCHEMA] `Supabase SQL`
- You will need to run: `ALTER TABLE logbook_entries ADD COLUMN feedback_notes TEXT;`

#### [MODIFY] `backend/routers/logbook.py`
- Update `StatusUpdateRequest` to include an optional `feedback_notes: Optional[str] = None`.
- In `update_entry_status`, pass the `feedback_notes` into the Supabase `.update()` call.

#### [MODIFY] `frontend/pau-interconnect-app/app/dashboard/...`
- Identify the Employer component where logbook entries are reviewed. Add a small text area for feedback when "Flagging".
- Identify the Student component where logbooks are viewed. Display the `feedback_notes` if the status is `flagged`.

### 4. Streaming Cover Letters

To eliminate the 5-15 second loading spinner, we will stream the cover letter text to the frontend as it is generated by the LLM.

#### [MODIFY] `backend/services/llm_service.py`
- Add a new function `generate_completion_stream()` that uses `yield` to return chunks from the LLM provider.

#### [MODIFY] `backend/routers/applications.py`
- Update `/draft-cover-letter` to return a `StreamingResponse` using the generator function.

#### [MODIFY] `frontend/pau-interconnect-app/.../CoverLetterGenerator.tsx` (or equivalent component)
- Change the `crossFetch` call to use the native browser `fetch` API, read from the `response.body.getReader()`, and append chunks to a React state variable in real-time.

## Verification Plan

### Automated Tests
- Run `pytest backend/test_main_api.py` to ensure core routing hasn't broken.
- Ensure the FastAPI server boots successfully with `uvicorn main:app`.

### Manual Verification
1. **CV Upload**: Upload a PDF CV and verify the UI responds almost instantly, while checking the database 5 seconds later to ensure `match_results` are populated.
2. **Email Sent**: Submit a test application and verify the email arrives with a clickable CV link rather than a heavy attachment.
3. **Logbook Flag**: Log in as an employer, flag a student entry with a note, log in as the student, and verify the note is visible.
4. **Streaming**: Click "Generate Cover Letter" and verify the text appears on the screen rapidly, word-by-word.
